### 2.3 P0：坐标系根因与 axis-aware 修正（✅ 实装并验证）

**根因**：`tactic_match.py` 判据按**半场俯视系**写（`:120` y 减小 = 朝筐），但 22/22 段实测是**横屏广播像素**，`tactic_match_real.load_clip` **无任何球场变换**。

**三证据**：
1. `SCREEN.CROSS 52 : DOWN 10` 完全反转（真实篮球下掩护远多于横掩护）。
2. n=1420 掩护 |dx| 中位 **8.4px** vs |dy| **3.4px**（横屏以横向为主 → `|dx|>=2|dy|` 系统性误标，**不是阈值问题**）。
3. **DRIVE / EXCHANGE / ROLL 全 0**（都依赖朝筐方向）。

🔴 **自动标定三路全失败**：`court_infer_lines` 构图前提不成立 / 木地板掩膜跨域失效 / 篮筐橙环把球和观众当篮筐 ⇒ **必须老程目视点选**。

**老程方向裁定（A3.1，重大）**：
> 「都是半场镜头，但都不全可见，基本只有一角最清晰，其他的在画面外或被遮挡。不用执着于场地，我们的核心是识别战术、分析战术，如果战术没用到四角，那就是场地内啊，很正常。」

⇒ 全 4 角单应对这批素材**普遍不可得** ⇒ 原「老程点 4 角 → P0 全俯视单应」路线**不再作 A 步硬门禁**。改为**在广播像素空间原生重定义原语**：「朝筐」方向由可见球场朝向判定，而非假设俯视 y 轴。

**实装**：`engine/tactic_match.py` 改 axis-aware
- `detect_primitives(..., orient=(bx,by))`；`bw` = 朝筐单位向量，`lat = (-bw_y, bw_x)`
- CUT/DRIVE「朝筐」= 位移·bw > 0
- `_screen_sub` 投影 `along = 位移·bw`、`lat = 位移·lat`；`|along| ≥ 2|lat| → DOWN`、`|lat| ≥ 2|along| → CROSS`
- `orient=None` 回退 `(0,-1)`，demo 向后兼容已验证

**老程全量标注 + PAN 扫描**（13 簇）：
- f_l = #5 #8 #11 #6 #13 #19；f_r = #15 #18 #22 #29 #9 #12 #16；#3 无场地
```
PAN   全13 CROSS:DOWN
 0   47:7   (0.15x)  ← 旧代码反转，与 A3 证据一致
45    3:10  (3.33x)  ← 翻转
60    4:27  (6.75x)
```

⇒ 反转在 **PAN≈45 翻转**，75–90 既分类数最大（~54）又 DOWN 占优（~6.7x）。**锁定 pan=80**（bw≈±0.985, ∓0.174）落 `norm_calib/orient_anchors.json`；`run_p0_broadcast_native.py` 可复现。

⚠️ 订正：早前记忆里"球检测 ≥90%"属**另一批素材/另一模块**（sas_lal），**不适用**于这批 tactic_notes 段。

#### 2.5.2 指标与静止门（两次纠错）
- **目的性** = 净位移 / 路程（1=有目的，0=抖动）
- **协同性** = 帧内位移单位向量平均长度（1=同向协同）
- **稳定性** = 跨 ≥70% 帧的球员占比
- **活跃度** = 中位速度归一化
- **顺畅分** = 0.35×目的性 + 0.30×协同性 + 0.20×稳定性 + 0.15×活跃度

**纠错①**：初版用「全员中位速度 < 1.5px」判静止 → 篮球里多数球员本就站着，中位天然低，**误杀真实进攻**（#5 明明检出过掩护/切却被判静止）。
**纠错②**：改「净位移 > 25px 者 = mover」→ **ID 切换瞬移**（一次大跳 + 其余静止）被当跑动者，#29 凭 3 个瞬移冲到第一（中位速度仅 0.16px/帧却 net>25px）。
**最终**：`mover` = 净位移 > 25px **且** 位移 > 1.5px 的帧数 ≥ 5（持续移动）；**< 3 movers 判静止剔出**。

老程逐条裁定：#11 f0=替补席镜头｜#22 f51=过渡特效｜#33 全非比赛画面｜#2 战术讲解+高亮放大｜#31 进球+替补席欢呼｜#27 战术开头+标题(short roll)｜#21 战术完结镜头｜**#12/#19 战术讲解画面，静止正常**。

### 5.2 🔴 未决难点（按阻塞度）

**① 轨迹统计无法区分"内容级"差异（最核心）**
顺畅分只量"球员是否协同移动"，但**替补席镜头、过渡特效、讲解画面、进球庆祝、开头标题、完结镜头**里球员照样在动。老程提议的"看具体有多少人出现在画面中"实测后**重叠严重**（KEEP 13~31 vs 剔出 8~30），**单指标不可分**。
⇒ 这是内容级/语义级判断，纯轨迹统计够不到。老程目视仍是唯一可靠门禁。

**② CUT 原语语义边界**
按老程定义 cut = "从三分线外向内快速移动"（时序运动，静态帧不可辨）。当前实现只判"朝筐投影 + 速度"，在广播半场"朝筐≈画面左移"下**把普通重定位记成切**（#8 40 个 CUT、净位移 40–532px）。通行距离门只剔纯抖动，**不根治**。

**③ ID 不稳定（门①-B，已知架构边界）**
同一球员被拆成多 track_id：#11 跑动者 48 但每帧仅 29 人；#8 涉 33 个 ID 而实际约 28 人。⇒ 所有按 ID 聚合的指标（跑动者数、协同、稳定）都带系统性虚高。

**④ 球检测不可靠**
真检出率 6.7%~59%、conf~0.2、900+px 瞬移 ⇒ 球轨迹**不能**用作顺畅度主判据，只能单列报告。若后续要用球，需先修检测或换信号源。

**⑤ 球场标定标注稀缺**
`court_calib/half_court_calib.json` **全库仅 ep24_s1 有，且 UNRESOLVED**；ep10–ep20 无标定。自动三路已证伪 ⇒ 依赖老程目视点选，而老程已裁定「不执着场地」。
