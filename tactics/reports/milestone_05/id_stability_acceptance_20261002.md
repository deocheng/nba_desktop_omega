## 七、门 ①-B「身份正确性」验收（老程拍板拆双门后补做）

### 方法
不需要任何人工帧级标签，自带对照：

- **T1 组间基线**：同一帧内不同球员两两外观余弦 cos → 「不同人」的对照分布
- **T2 组内同 ID**：同一 track 内相隔 L 帧的两帧余弦 → 「同 ID 同一人」的假设
- 外观 = DINOv2-small CLS 384d（L2 归一，stabilize_tracks_v2 现成用）
- 指标：Δ10 = mean(within@10) − mean(between)；win_rate = P(within@10 > between)；Cohen's d

### 判据（跑之前注册，禁止事后调线）
- P1 主判据：Δ10 ≥ **0.15**
- P2 副判据：track 内相邻帧外观突变（cos<0.5）占比 ≤ **5%**
- P3 单调性：within@1 ≥ @5 ≥ @10 ≥ @20
- 三者全过 ⇒ ①-B PASS

### 结果（样本量充足后，12/12 全过）

| 配置 | 段 | n@10 | Δ10 | win_rate | cohen_d | ①-B |
|---|---|---:|---:|---:|---:|---|
| 默认 | det/hou/lal/nop | 3083/2745/2723/3495 | 0.228/0.224/0.272/0.275 | 0.82/0.83/0.89/0.82 | 1.56/1.44/1.86/1.73 | PASS ×4 |
| g0 (buf300/600) | det/hou/lal/nop | 3038/2683/2726/3451 | 0.230/0.230/0.270/0.277 | 0.82/0.82/0.88/0.80 | 1.58/1.47/1.83/1.75 | PASS ×4 |

### 🔴 自我推翻记录（本轮最重要的一条）
**第一版审计跑出「g3 身份 0/4 FAIL、默认 2/4 PASS」，据此我一度主张"rescue-g3 的长寿命是空心成绩"。这个结论错了**，错在两条我自己的实现 bug：

1. **配对写错**：只取 track 帧序列里**相邻两项**的间隔当 L ⇒ L 只能等于「实际漏检长度」，
   于是 n@10 塌到 **6~13** 个样本、n@20 只有 1~3 个。主判据建在个位数样本上 = 噪声。
   修正为枚举 track 内**任意**跨 L 帧的两帧后，n@10 → **2700~3700**。
2. **P3 被 n=1 决定**：sas_nop 的 within@20=0.82 反高于 @10=0.54，一度判失败。
   查证该 lag=20 只有 **1 对样本，位移 0.5px**（一个完全站定不动的球员），
   外观不变是**正确行为**，不是身份漂移 ⇒ **P3 单调性这条判据本身不成立**，已作废
   （站桩球员外观本就不该变，单调性是既不必要也不充分）。

修正后 Δ10 = 0.21~0.28，距 0.15 门槛有充足余量，Cohen's d 1.3~1.9（大效应）——
**结论翻转：g3 的身份一致性并不比默认参数差，①-B 四段全过。**

## 八、全语料 177 段批量 × 门 ①-A 验收（本轮新增）

### 8.1 这轮要解决的问题

第七节的结论只建在 sas_* 四段（早期顶层目录，**不在 177 段语料里**）。
要把「净化门」真正落地，必须先解决三件事：
① `ep*_sX` 的段源 `ball_tracks.json` 是**未过滤原始检测**（每帧 25~27 框，直接喂稳定化会撞死并发门）；
② 过滤阈值当时是从聚合统计里拍的 **conf≥0.40 + 框高 h≥80**；
③ 全语料批量要能**逐段留痕 + 断点续跑**。

### 8.2 🔴 自我推翻 1：h≥80 是错的（绝对像素高度对景别不鲁棒）

全语料 177 段扫描后，把 31 段「每帧人数 <8」的段单独拆开看，结果完全不是检测器漏检：

| 段 | 原始框数/帧 | conf≥0.40 + **h≥80** | conf≥0.40 单独 |
|---|---:|---:|---:|
| ep69_s1 | 21 | **5** | 21 |
| ep14_s1 | 20 | **6** | 20 |
| ep31_s0 | 18 | **5** | 18 |
| ep41_s1 | 13 | **4** | 13 |
| ep4_s1 | 9 | **5** | 9 |

⇒ 是**宽景镜头里球员本身就小，h≥80 把真球员砍光了**。绝对高度阈值只在「半场中近景」成立，
换个镜头就崩。根因不是检测召回，是**度量单位选错**（像素 vs 相对尺度）。

**换成景别无关的口径**：每帧只保留 `conf≥0.40` 里**框最高的 12 个**。
物理依据 = 篮球规则（半场同时 ≤10 球员 + ≤3 裁判 ≈ 12~13 人），与镜头远近无关。

| 过滤口径 | 落在 [8,16] 的段数 | 全语料每帧人数中位 |
|---|---:|---:|
| conf≥0.40 + h≥80（上一版） | 122/177 | 9.0 |
| conf≥0.40 | 147/177 | 12.0 |
| **conf≥0.40 + 每帧最大 12（采用）** | **171/177** | 12.0 |

**视觉自证**（不是只看统计）：渲染 ep77_s0 f60 / ep69_s1 f50 的 top-12 框，
全部落在真实球员身上，远端小球员（conf 0.34~0.42）也在其中；
对照 h≥80 版本只留 5 个（/tmp/topn_ep77_s0.png、/tmp/topn_ep69_s1.png）。

### 8.3 🔴 自我推翻 2：「重复 ID / 一人分多 ID」假设被证伪

超密段（并发 17~18）怀疑是 ID 分裂，写了 `engine/post_stabilize_dedup.py` 去验。
先做一个决定性检查——同一帧内两两框的 IoU：

```
ep77_s0 f60：17 个框，同帧最大 IoU = 0.135（id1↔id7），第二高 0.119（id2↔id3）
⇒ 17 个框是 17 个互不重叠的真人（框高 87~171px 全在球员量级）
```

再回头看那几对"共现 >80% 帧、IoU 0.5~0.7"的轨：
相交帧只有 **1~44 帧**，其余 130~170 个共现帧两框根本不重叠。
⇒ 是同时在场的两组人，**不是一个人切成两个 ID**。
`post_stabilize_dedup.py` 在全语料上的合并数 = **0**（脚本保留，作为反证工具）。

⚠️ 这里我自己的脚本也踩了两个坑，都记下来：
① IoU 拿「全部共现帧」平均 → 不相交帧贡献 0，把真重合冲没（必须只统计**相交帧**）；
② 切镜判据拿单帧 id 集合比 → 一次漏检就误判切镜（一段被切成 8~22 个假窗口），
   改成「与**前 3 帧 id 并集**的重合率」才正常。

### 8.4 🔴 结构性发现：门①-A 的「并发」在过滤后退化成「数输入」

18 段样本上实测 **保真率 = 稳定化并发中位 / 输入框中位 = 1.00（18/18 精确相等）**，
全语料中位保真率 1.000、Δ(并发−输入) 中位 **+0.00**。

⇒ 稳定化**既没制造碎片、也没错并**，每帧每个可见人恰好一个 ID（这是好消息）。
但也说明：**并发这个数在过滤后基本等于输入检测数**，它测的是上游检测密度，不是稳定化质量。
真正由稳定化决定的只剩「中位寿命」。

### 9.1 门 ①-A 本身的口径建议（本轮新提，需老程裁定）

实测暴露了两个口径问题，都不是"调线调过的"：

1. **绝对并发带 [8,16] 是"半场中近景"假设下的数**，对**特写**（场上就 5~7 人）和
   **超宽景**（含场边人员 17~18 人）都不成立。7 段未过里 6 段属于这一类，稳定化无责。
2. **保真率（并发/输入）才是稳定化自己的指标**：全语料中位 1.000、Δ=+0.00，
   说明 G3 既没碎片也没错并。建议：
   - 硬判据 = **保真率 ∈[0.80,1.25] 且 中位寿命 ≥30**（本轮 174/177 = 98%）
   - 绝对并发带 [8,16] 降级为**监控量**（它主要反映上游检测密度）
3. ⚠️ **一个必须声明的循环依赖风险**：本轮采用的 `--topn 12` 与老门槛上界 16 都来自
   "≤10 球员+裁判"这个物理数。topn=12 会把 101/177 段压到恰好 12，
   **客观上使上界 [8,16] 不可能被顶破**。所以「96% vs 98%」这个差距不能反过来当证据，
   独立支撑只有 **保真率 1.000 + 中位寿命 110 帧**。

## 10.2 🔴 推翻「用 id 集找切镜」：前提不成立

第九章建议「门①-A 按镜头窗口分别算」，但窗口怎么切，先把工具验了：

**① id 集切镜不可用。** 稳定化 `track_buffer=300 / zombie_buffer=600` 会把 id **直接拖过切镜点**：

```
ep24_s1  f90  ids = {1,2,3,4,6,8,9,11,12,13,14,15}
         f96  ids = {1,2,3,5,6,8,10,11,12,14,15,16}   ← 12 个里 10 个是老 id
```

⇒ 任何「相邻帧 id 重合率骤降 ⇒ 切镜」的判据都只会得到噪声。
A5.31c 那版「68/177 段含切镜」正是这么来的（ref=3 的三帧滑动窗，任何一个人新进画面就触发），**作废**。
加固后（持续 5 帧 + 最短窗 10 帧）它给出的结果是 **0/177**，矫枉过正。

**② 框高跳变也不行。** ep24_s1 跨切镜框高 111→119→116→116，几乎不跳（两镜头取景相似）。

**③ 像素可以，但只能给出上界。** `engine/shot_cut_detect.py`（160×90 灰度逐帧，
相邻帧平均绝对差 MAD，尖峰 >3.5× 段内中位）：
- ep24_s1 尖峰在 f94 / f155（5.1× / 4.8×），对上 A5.27 判定的 93→95 / 154→156，误差 1 帧 ✅
- ep9_s1 f60 是**真·大切镜**（整幅画面换机位）✅ 视觉已证

但视觉自证同时暴露它的局限：**同机位时间跳切与换机位真切镜分不开** ——
ep24_s1 的 f92/f94/f96 看上去是连续同机位（只有球员位置时间上跳了一下），
MAD 却尖峰了。全语料 177 段扫出 **1005 处切镜、168/177 段含切镜**，
均值 5.7 处/段，其中 ep9_s1 达 17 处（每 13 帧一跳）——**这个数只能当上界，不能当精确窗口数**。
