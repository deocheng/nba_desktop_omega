## 2. 过滤规则

球点物理可支撑性定义：`d_rect` = 球心到**最近球员框矩形**的距离（落在框内 = 0）。
支撑阈值 `support_px = 0.04 × 帧对角线 = 88.1px`（与 `ball_possession.py` 的 `poss_radius` **同源**，不新造常数）。

| 层 | 规则 | 判定 |
|---|---|---|
| **R1** | 轨迹内存在 ≥1 个点 `d_rect ≤ 88px` | **KEEP**（保护传球/投篮：轨迹两端总有一端靠近球员） |
| **R2**（可选，默认关） | 无支撑但 `mean_step ≥ min_step` | KEEP（保护纯飞行段） |
| 否则 | 全程离所有球员 >88px | **DROP** |

**为什么轨迹级而不是逐帧**：逐帧删会把「投篮弧线顶端」「传球飞行段」的真球误杀；
轨迹级只需轨迹**任一端**落在球员附近即可保全整条。且 `min_track=3` 已在 A4.15 证明能滤掉单帧/双帧 FP。

复用 A4.18 已产出的球员框（`<clip>_poss_tile/ball_tracks.json`，400 帧全量），**零额外 GPU 计算**。

## 5. 两个方法论发现

### (a) 门禁 `trackable_frac` 与**精度反相关**（重要）

`trackable_frac` = 轨迹内相邻步位移 <80px 的比例，设计初衷是「真球平滑连续、FP 乱跳」——
**这个前提对「静态伪目标」不成立**。观众席光斑 / LED 计时器 / 转播角标是**几乎静止**的
（被删轨迹 `mean_step` = 12–18px，甚至 1.3px），它们**免费拿到 trackable_frac ≈ 1.0**。

因此：删掉平滑 FP 后，剩下的步骤更"跳"，指标**必然下降**——
sas_nop 78.8%、sas_det 0.3 档 70.0% 都是这个机制，不是"变差了"。
**结论：`trackable_frac` 是「事件连续性/可用性」指标，不能当精度验收口径**；
用它反向指导精度过滤会**系统性奖励 FP**。本项的正确验收口径是 §4 表 4（下游功能指标）+ §3（目视）。

### (b) `max(conf)` 平局按列表序 → 隐藏的 tie-break 隐患

`ball_possession.py:216` 取每帧「最高置信候选」，平局时 `>` 比较使**先入列表者胜**。
实测 sas_hou f00038：FP 与真球候选 **conf 完全相同（0.97 vs 0.97）**，FP 恰好排在前面 → 真球被顶掉。
本例被 FP 过滤**顺带修好**（FP 先被删掉），但这是**偶然的**：
更稳妥的做法是平局时用「离最近球员更近」作为 tie-break。**建议列入后续（本轮未改，避免扩大改动面）。**
